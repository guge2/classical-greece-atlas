## 三、地名核定

75 个规划地名全部落实到 Pleiades 条目，去重与合并后为 74 个标记。经与 Wikidata 中文标签交叉核对，修正两处音译：

- **纳夫帕克托斯 → 瑙帕克托斯**：前者是现代希腊语 Nafpaktos 的读法，古典语境通行译名为瑙帕克托斯（别名保留）。
- **尼多斯 → 克尼多斯**：原拟译名漏译词首辅音 K，Wikidata 中文标签亦作克尼多斯。

其余地名维持规划用字。Wikidata 与人工译名的差异（繁体写法、现代地名、带限定语的条目名）逐条记录在 `data/derived/wikidata_check.csv`，未自动覆盖任何人工译名。

## 四、执行中的判断与偏离

1. **锡巴里斯与图里伊合为一个标记**。Pleiades 把二者归入同一处遗址（452457，Sybaris/Thurii/Copia），图里伊建于公元前 444 年、与锡巴里斯故址同处一地，两点在 1:2 540 000 下不可分辨。因此保留两个名称、合为一个标记，标签作「锡巴里斯／图里伊」。规划的 25 处地名全部出现在图上，标记数为 24。
2. **德洛斯与斯法克特里亚没有对应岛屿多边形**。二者面积（约 3.5 km² 与 0.8 km²）低于 Natural Earth 1:10m 的最小岛屿，底图中不存在相应多边形，无法「强制保留」。二者按制图惯例以点符号加名称表示，位置仍取自 Pleiades。
3. **克尼多斯取古典城址**。Pleiades 有两条：布尔加兹（古风—古典时期城址，599576）与特基尔（希腊化后迁址，599575）。地图服务于公元前五世纪，故取布尔加兹，并在 `note` 中注明。
4. **罗得斯取城市点位**。罗得斯城建于公元前 408 年，属五世纪末，`note` 中已注明。
5. **实际成图范围大于配置范围**。四图共用同一图廓（304 × 242 mm，宽高比 1.256），而本土、爱琴海、西西里三图的配置范围接近正方形，因此在投影平面上按图廓比例居中扩展。扩展只增加周边海域与陆地上下文，不改变要求的范围，也不产生变形。代价是西西里图西侧与总览图南侧留有较大面积的空白海面。
6. **海岸概化容差随版面改版重算**。规格给出的 5 km / 1.5 km 是按原版面的比例尺定的；满版铺开后比例尺放大了 23%–38%，若沿用原数值，打印后的折线感会同比变粗。因此改为总览 3.6 km、区域图 1.2 km，使打印后的最大偏移仍为约 0.9 mm 与 0.63 mm，与规格数值在原比例尺下的效果一致。小面另按自身尺度收紧容差，以免命名岛屿塌形。文件体积距上限仍有较大余量，如需更精细的海岸，继续调小 `maps.yaml` 的 `simplify_km` 即可。
7. **最小岛屿阈值同步放宽**（总览 25→15 km²，区域图 8→5 km²），因为同样面积的岛屿在放大后的图上占更多版面，值得画出来。

## 五、开发过程中修复的缺陷

- **图廓裁剪路径错误**（PDF/PNG 后端）：`Rectangle.get_path()` 返回的是未经变换的单位矩形，导致整层陆地被裁掉，页面上看到的「陆地」其实只是地形影像。改为按图廓毫米坐标显式构造裁剪路径。
- **SVG 小数格式化把字号缩放舍成 0**：文字用 `translate(...) scale(k,-k)` 定位，k 约 0.0026，而坐标格式化固定保留两位小数，`scale(0 -0)` 使副标题与全部小号标签在浏览器中消失，标题也偏大约 29%。改为对缩放因子按有效位数格式化，并用浏览器复核了 SVG 实际渲染结果。

改版满版布局时又暴露出两个问题，也已修复：

- **对角方位的偏移量小于标记半径**：东北、东南等方位的候选位置会与地点自身的符号相撞，白白损失四个可用方位（错误信息里出现「东北被符号 erythrae 挡住」这种自相矛盾的提示）。已把对角偏移提高到与正交方位同量级。顺带给 `LabelConflict` 增加了逐方位的阻挡原因，排版冲突现在能一眼看出是被谁挡住。
- **PDF 不再嵌入字体子集**：新版面给标题、比例尺与页脚也加了光晕，而 matplotlib 一旦给文字加 `path_effects` 就改用路径绘制，结果整份 PDF 里一个字体对象都不剩。改为光晕与正文分两遍绘制——光晕走 path effect，正文不带任何 effect，因此保持为可嵌入子集、可检索的真实文字，与 SVG 后端「光晕组 + 填充组」的结构一致。这一条是 `atlas.check` 自己报出来的。

SVG 缩放因子那一条只影响 SVG 后端；由于两个后端共用同一场景，PDF 版面自始至终正确，这也是把版面计算与输出格式分离的价值所在。
